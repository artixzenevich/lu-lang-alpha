# Установка lu-lang в систему

В этом документе — как развернуть язык **lu** на машине на постоянной основе,
чтобы команда `lu` была доступна из любого каталога. Документ про Linux
(под macOS и Windows порядок похож, но проверялся на Linux).

> Начав пользоваться одним способом, придерживайтесь его: и скрипт, и
> бинарник кладут команду в одно место (`~/.local/bin/lu`), последняя
> установка побеждает.

---

## Требования

- **Linux** (проверялось на NixOS и Debian-подобных).
- Для способа **1** (скрипт): Python **3.10 или новее**.
- Для способа **2** (бинарник): Python нужен **только для сборки**, на
  целевой машине не нужен.
- Каталог `~/.local/bin` в `PATH` (или установка с `--prefix` в каталог,
  который уже в `PATH`).

### Библиотека «черепашка» и Tk

Графическая библиотека `черепашка` работает поверх модуля `turtle`
из стандартной библиотеки Python, а тот требует **Tkinter** (`tk`). Если
Tk нет — `подключить черепашка` завершится ошибкой.

- **Способ 1** (скрипт): Tkinter должен быть в том Python, которым вы
  ставите язык. На NixOS системный `python3` обычно без Tk:
  ```bash
  nix-shell -p 'python3.withPackages (ps: [ ps.tkinter ])' --run './install.sh'
  ```
  Debian/Ubuntu: `sudo apt install python3-tk`. Fedora: `sudo dnf install python3-tkinter`.
- **Способ 2** (бинарник): Tkinter нужен **только в окружении сборки** —
  собранный бинарник уже содержит и `turtle`, и Tk, целевая машина
  ничего дополнительно ставить не должна (см. ниже).

Если `~/.local/bin` отсутствует в `PATH`, скрипт `install.sh` сам добавит
его в `~/.bashrc` / `~/.profile` / `~/.zshrc` (создаёт запись с метками
`# >>> lu-lang >>>` / `# <<< lu-lang <<<`).

## Способ 1. Установка скриптом `install.sh`

Скрипт создаёт виртуальное окружение **вне проекта** (по умолчанию
`~/.local/share/lu-lang/venv`), устанавливает в него пакет и ставит команду
`lu` в `~/.local/bin`. Установка **standalone**: пакет копируется в окружение,
от каталога проекта она не зависит — репозиторий после установки можно удалить.

```bash
./install.sh
```

После установки откройте новый терминал (или `source ~/.bashrc`) и проверьте:

```bash
lu --version            # lu-lang 0.8.2-alpha
lu examples/hello.lu    # примеры запускаются
```

### Опции

| Команда | Что делает |
|---------|-----------|
| `./install.sh` | Установить (или переустановить) в `~/.local/bin` |
| `./install.sh --update` | Переустановить пакет из текущего каталога (`pip install --force-reinstall`) |
| `./install.sh --dev` | Для разработки: editable-установка в `.venv` проекта |
| `./install.sh --prefix DIR` | Установить команду в `DIR/bin` |
| `./install.sh --venv DIR` | Использовать виртуальное окружение `DIR` |
| `./install.sh --python PY` | Какой интерпретатор использовать (по умолчанию `python3`) |
| `./install.sh --uninstall` | Удалить команду `lu`, окружение и строку из `PATH` |
| `./install.sh --help` | Справка |

Переменные окружения: `PREFIX`, `LU_VENV`, `LU_SHARE`, `PYTHON` — работают
как соответствующие опции.

### Обновление после изменений в языке

```bash
git pull                 # в каталоге проекта
./install.sh --update
```

### Удаление

```bash
./install.sh --uninstall
```

Скрипт удалит `~/.local/bin/lu`, окружение `~/.local/share/lu-lang/venv`
и уберёт добавленную строку из файлов профиля.

## Способ 2. Бинарник (PyInstaller), `build.sh`

Сборка даёт **один исполняемый файл** `dist/lu` — Python на целевой машине
не нужен. Встроенные библиотеки (`математика`, `время`, `черепашка`)
вшиваются в бинарник автоматически, а вместе с ними — **вся стандартная
библиотека Python** (`math`, `time`, `json`, `sqlite3`, `turtle`, `tkinter`,
`http`, `xml` и т.д.), так что любой модуль-плагин заработает и на другой
машине без доустановки чего-либо. Бинарник весит ~19 МБ.

```bash
./build.sh               # собрать и установить в ~/.local/bin
```

Проверка:

```bash
lu --version
lu examples/черепашка.lu   # графический пример — нужен экран
```

### Опции

| Команда | Что делает |
|---------|-----------|
| `./build.sh` | Собрать и установить в `~/.local/bin` |
| `./build.sh --no-install` | Только собрать (результат: `dist/lu`) |
| `./build.sh --prefix DIR` | Установить в `DIR/bin` |
| `./build.sh --clean` | Пересоздать окружение сборки (`--clean` + сборка) |
| `./build.sh --python PY` | Интерпретатор для сборки |
| `./build.sh --help` | Справка |

### Как это работает

1. В `.build-venv` ставится `pyinstaller` и сам пакет;
2. `pyinstaller --onefile --name lu --collect-all lulang ...` собирает
   бинарник. Флаг `--collect-all lulang` нужен, чтобы файлы
   `lulang/библиотеки/*.lu` и `*.py` (модули подгружаются динамически)
   попали в bundle. Вся стандартная библиотека Python добавляется
   явным списком скрытых импортов (`--hidden-import=<модуль>` для каждого
   модуля stdlib): PyInstaller не видит динамические импорты из
   библиотек-плагинов, поэтому без этого в бинарнике оказалась бы лишь
   часть stdlib;
3. После сборки бинарник самопроверяется: `--version`, примеры
   `hello.lu`, `модули.lu`, встроенные модули `математика` и `черепашка`,
   а также доступность ~50 ключевых стандартных библиотек через
   временный модуль-плагин;
4. По умолчанию бинарник копируется в `~/.local/bin/lu`.

> Если окружение сборки без Tk, `build.sh` выведет предупреждение:
> «черепашка» в бинарник не попадёт. На NixOS соберите окружение с Tk:
>
> ```bash
> nix-shell -p 'python3.withPackages (ps: [ ps.tkinter ])' --run './build.sh --clean'
> ```

### Обновление

```bash
git pull
./build.sh
```

### Удаление

```bash
rm -f ~/.local/bin/lu
```

Бинарник не оставляет других следов в системе.

### Сборка под другую ОС

PyInstaller не кросс-компилирует: собранный под Linux бинарник работает
только под Linux. Для macOS/Windows нужна сборка на соответствующей машине
(или в CI). Данные о целевой платформе стоит учитывать при распространении.

## Способ 3 (на будущее): pip / pipx

Пакет можно публиковать на PyPI и ставить стандартным путём:

```bash
pipx install lu-lang          # изолированное окружение + команда в ~/.local/bin
pipx upgrade lu-lang          # обновление
```

Либо `pip install lu-lang` в подходящее окружение. Этот способ станет
основным после релиза 1.0.0.

## Проверка установки

```bash
lu --version
lu examples/hello.lu
printf 'запомнить x = 2\nпечать(x * 21)\n' > /tmp/проверка.lu && lu /tmp/проверка.lu   # 42
```

## Возможные проблемы

- **`lu: command not found`** — каталог `~/.local/bin` не в `PATH`.
  Либо выполните `source ~/.bashrc` в новом терминале, либо добавьте
  `export PATH="$HOME/.local/bin:$PATH"` в файл профиля.
- **`No module named 'lark'`** (способ 1) — пакет не установился полностью;
  повторите `./install.sh --update`.
- **Бинарник не запускается на другой системе** — бинарник привязан
  к платформе и версии glibc машины сборки; собирайте на целевой ОС.
- **PyInstaller и новая версия Python** — если сборка падает с
  несовместимостью, используйте `./build.sh --python python3.12` (или 3.11).
- **`подключить черепашка` падает с `No module named 'turtle'`** — в среде
  нет Tkinter. Способ 1: поставьте Python с Tk (см. «Библиотека „черепашка"
  и Tk» выше) и переустановите. Способ 2: пересоберите бинарник в
  окружении с Tk.
- **`подключить черепашка` падает с ошибкой про дисплей** — на машине нет
  графического экрана; это ожидаемо, черепашка требует дисплея.
